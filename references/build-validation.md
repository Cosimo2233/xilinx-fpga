# 构建与验证

按实际技术栈读取相关部分。命令和工程格式以当前安装版本的帮助、已有脚本及厂商文档为准。

## 纯 RTL / Vivado

- 核验完整器件型号、设计顶层、仿真顶层、文件集、包含路径、初始化文件和约束；确认源码真正进入工程。
- 仿真检查本次变化涉及的复位、边界输入、有效数据与控制时序。流接口关注背压、连续事务、数据顺序和边界标记；按模块能力选择场景。
- 完整构建依次确认综合、实现及目标产物生成的实际状态和日志。已经结束但需要刷新的 run 应按当前设计重新执行。
- 资源结论使用与交付阶段匹配的报告。顶层 OOC 黑盒/stub 统计不包含全部 IP；不能据此宣称整机资源极低或为零。
- 报告时序时同时查看建立、保持及适用的脉宽检查，检查未约束时钟/端点和关键 methodology 警告。
- “已设置约束满足”只覆盖已有约束范围；若外部接口约束不完整，说明对应限制。对例外约束保留设计依据。

## HLS 集成

- 明确数值类型、位宽、舍入/溢出规则、数组/帧界限、接口协议及需要达到的性能条件。参考实现独立表达预期行为。
- 根据变化执行 C 仿真、HLS 综合和必要的 C/RTL 协同仿真。检查实际输入范围、边缘尺寸、连续调用及项目所用配置。
- 对流或控制接口的改动，验证数据数量、TLAST/TUSER 等实际使用的边界语义、背压、复位与完成状态。软件测试覆盖不能自动等同于这些接口行为已在 RTL 中验证。
- 保持 HLS 源码、导出 IP 和 Vivado 引用一致；更新核后重新生成并集成对应 IP，避免继续引用旧导出目录。
- HLS 估算时钟、II、延迟和资源属于核级结果。集成后的完整时序与资源通过 Vivado 实现检查，系统吞吐依据适用的实际测量。
- 新增协同仿真脚本时使用当前 Vitis/HLS 版本支持的接口，不把某一代工具的启动方式写成通用常量。

## SoC / Vitis 与配套软件

- 明确 PS/PL 模块分工、地址映射、寄存器、数据布局、缓存一致性、中断、时钟复位以及软件与硬件的版本对应关系。
- DMA 或共享存储需要检查长度、对齐、缓冲区所有权、完成与错误状态。涉及帧/事务标识时，确认返回结果能对应请求。
- 导出实际使用的硬件交接文件，按平台需要配置软件域、BSP、启动组件或 Linux 设备树与驱动。
- Vitis 平台导出、软件编译、Linux 启动和真实外设运行分别验证。Linux Python 等应用通过相应运行环境交付，不把导出 XSA 视为应用已编译或部署。
- 可在缺少板卡时验证主机参考、接口仿真、硬件构建及可用的软件构建。实际启动、连续传输、缓存/驱动、外设行为和性能仍需目标硬件验证。

## 结果与产物一致性

| 已完成的检查 | 可以陈述的结果 |
|---|---|
| 工程文件生成、BD 校验及引用检查 | 工程结构已生成并通过相关检查 |
| 行为仿真或协同仿真 | 指定场景下的行为检查通过 |
| 综合 | 当前综合配置完成，相关资源估算可用 |
| 完整实现及适用时序检查 | 当前实现满足已核验的约束范围 |
| bitstream / 平台文件导出 | 对应硬件产物已生成 |
| 实际目标硬件运行与测量 | 已测场景的上板行为或性能得到验证 |

部署产物从同一成功构建中导出。按平台需要选择 bitstream、硬件描述、XSA、启动文件或软件镜像；不要求每个 FPGA 工程都产生所有格式。
当硬件描述和 bitstream 需要成对使用时，确保二者来自同一构建；交付清单记录工具/器件版本、构建身份、关键文件及校验值。
有条件时检查交接包中包含的文件与独立导出的对应文件一致，避免混用旧产物。

最终说明应简洁覆盖：实际运行的验证、对应输入或场景、主要结果、未解决的构建问题和未完成的上板项。
工具、许可证或 BSP 缺失时准确说明阻塞的阶段；不根据脚本完整、旧日志或产物存在推断未执行的检查已通过。
